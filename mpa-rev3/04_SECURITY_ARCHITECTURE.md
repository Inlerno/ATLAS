# 04. Security Architecture (REV3)

**Статус: PROPOSED.** Документ сводит модель угроз и инварианты. Механизмы описаны в документах 05 (сопряжение и аутентификация), 06 (авторизация), 07 (журнал), 08 (сеть и лимиты), 09 (Secrets). Независимое (не Claude) ревью этого раздела рекомендуется до G3 (риск R-30).

## 1. Активы

| Актив | Где | Почему важен |
|---|---|---|
| Управление ПК (команды Stage 5) | Desktop | наибольший ущерб при злоупотреблении (ADR-008) |
| Управление модулями, настройки | Desktop | изменение поведения ассистента |
| История и память | Desktop / телефон | личные данные |
| Ключ TLS Desktop | Secrets (Desktop) | подмена Desktop для телефонов |
| Ключи устройств | Keystore / Keychain | вход от имени устройства |
| Реестр устройств, журнал, аудит | SQLite Desktop | целостность прав и истории действий |

## 2. Нарушители

| Нарушитель | Возможности |
|---|---|
| N1 — посторонний в той же Wi-Fi-сети | видит и отправляет трафик в LAN |
| N2 — посторонний в Интернете | только при открытом наружу порту (не поддерживается; VPN — документ 08) |
| N3 — владелец украденного или потерянного телефона | доступ к разблокированному или заблокированному устройству |
| N4 — вредоносный код в WebView телефона или Desktop | исполняет JS в контексте приложения |
| N5 — оператор VPN или будущего relay | видит метаданные и зашифрованный трафик |
| N6 — злоумышленник, видящий экран Desktop при сопряжении | может сфотографировать QR |

## 3. Границы доверия

| Граница | Что пересекает | Контроль |
|---|---|---|
| WebView ↔ Rust (телефон) | высокоуровневые команды `remote_*` | WebView не имеет сети, ключей и pin set (документ 02 §2.1) |
| Телефон ↔ Desktop (сеть) | TLS 1.3 | pin SPKI, аутентификация соединения ключом устройства (05) |
| Remote Access ↔ прикладные функции | вызовы с `RequestContext` | уровни, журнал, лимиты (06, 07, 08) |
| Прикладные функции ↔ Module Manager / Policy | существующие контракты | ADR-012 (план и подтверждение), Policy Stage 5 |
| Desktop WebView ↔ Rust (Desktop) | Tauri IPC | IPC доступен только коду приложения [ВНЕШН: Tauri capabilities]; с `csp: null` внедрённый скрипт работает как код приложения → **CSP — предусловие** доверия `source = DesktopUi` (F-17 ревью) |
| Remote Access ↔ Secrets | операции с ключом | доступ только к своему пространству имён (09 §5) |

## 4. Угрозы и меры

| Угроза | Нарушитель | Мера | Документ |
|---|---|---|---|
| Подключение к Desktop из LAN без сопряжения | N1 | listener выключен по умолчанию; только сопряжённые ключи; привязка к выбранному интерфейсу | 03 §2.1, 05, 08 §3 |
| Подмена Desktop (MITM) | N1, N5 | pin SPKI; TLS 1.3; нет «доверять всё равно» | 02 §4 |
| Перехват сопряжения через QR | N6, N1 | одноразовый секрет ≥128 бит, ≤5 мин; привязка к TLS exporter; подтверждение на Desktop с коротким кодом на обоих экранах | 05 §2 |
| Кража телефона | N3 | отзыв на Desktop; биометрия для подтверждений; ключи не экспортируются | 05 §7 |
| Повтор перехваченной команды | N1, N5 | TLS; одноразовые challenge; дедупликация `(device_id, request_id)`; подпись привязана к `intent_hash` и challenge | 07 §4 |
| Повторное выполнение после потери ответа | — | журнал, `outcome_unknown`, запрет автоповтора | 07 |
| Выполнение по устаревшим правам | N3 | проверка прав в той же транзакции, что переход в `executing`; `grant_version` | 06 §6 |
| Подмена текста подтверждения | N4 (телефон) | текст строит Rust, показывает системный диалог | 02 §2.1 |
| Обход проверок через WebView | N4 | сеть и ключи только в Rust/native | 02 |
| Вытеснение локального управления, DoS | N1 (сопряжённое устройство), N3 | лимиты, одна удалённая команда в Module Manager одновременно, очередь с таймаутом | 08 §6 |
| Рост аудита и журнала | N1, N3 | лимиты частоты, ротация и ограничения размера | §6 |
| Утечка секретов в логи и диагностику | — | типы с маскировкой, запрет хранения секретов в SQLite | 09 §6 |
| Удалённое выполнение произвольных команд | любой | нет маршрута с текстом команды; только Policy (Stage 5) | 06 §4.4 |
| Подделка `source`, `device_id`, `principal` | любой клиент | атрибуты определяет сервер; поля клиента игнорируются | 06 §2 |

## 5. Инварианты (будущие автоматические тесты MPA-2)

| # | Инвариант | Проверка |
|---|---|---|
| I-1 | При выключенном Remote Access нет открытого сокета | тест + ручная проверка Windows |
| I-2 | Без аутентификации соединения недоступна ни одна операция, кроме `session/*` | тест маршрутов |
| I-3 | Отозванное устройство отклоняется на следующем запросе; его соединения закрыты | тест |
| I-4 | Изменение модулей удалённо возможно только через `plan` → `apply` с `acknowledged` | перечисление маршрутов + тест |
| I-5 | Нет маршрута с текстом shell, SQL или параметрами подписки на шину | ревью + тест |
| I-6 | Поля `source`, `device_id`, `principal` от клиента игнорируются | тест |
| I-7 | Пересылаются только события из allowlist в рамках уровня | тест |
| I-8 | Повтор `request_id` никогда не приводит к повторному выполнению | тест жизненного цикла |
| I-9 | Журнал и аудит не содержат значений настроек, текстов и подписей в открытом виде | тест |
| I-10 | Переход в `executing` невозможен без действующих прав на момент перехода | тест гонки (06 §6) |
| I-11 | После шага 0 завершения Remote Access ничего не пишет в Storage | тест завершения |
| I-12 | Секреты не попадают в SQLite, логи и экспорт диагностики | тест + ревью (09 §6) |

## 6. Аудит

| Свойство | Решение [ПРЕДЛ] |
|---|---|
| Что записывается | сопряжение, отзыв, изменение уровня, включение и выключение Remote Access, начало и конец соединений, отказы аутентификации, каждый переход состояния запроса с побочным эффектом, отказы авторизации |
| Что не записывается | значения настроек, тексты сообщений, подписи, ключи, nonce |
| Хранение | таблица в SQLite Desktop (миграция — ревью владельца, ADR-016); только добавление (нет операций изменения в API `storage`) |
| Целостность | от изменения локальным пользователем с правами на файл не защищает. Нужна ли цепочка хэшей — решение владельца при MPA-2 (риск R-22) |
| Рост | лимиты частоты (08 §6); ограничение по объёму или сроку с удалением старых записей [ПРЕДЛ: 90 дней]; агрегирование повторяющихся отказов |
| Доступ | только локально на Desktop (документ 06 §4.5) |

## 7. Требования к TLS

TLS 1.3 только; набор шифров по умолчанию выбранной библиотеки (выбор — с ревью зависимостей и лицензий); ключ Desktop ECDSA P-256 [ПРЕДЛ]; SPKI pinning; аутентификация клиента — на прикладном уровне ключом устройства (документ 05 §4), а не клиентскими сертификатами: использование неэкспортируемого ключа Keystore/Secure Enclave в TLS-стеке Rust не проверено (риск R-25). Библиотека TLS влияет на export compliance в App Store (документ 13 §5).

## 8. Frontend и CSP

- Desktop: `csp: null` (`tauri.conf.json:21`) — до открытия сети должен быть задан CSP (#13 «Следующие issue»); это условие G3.
- Mobile: CSP без сетевых адресов Desktop в `connect-src` (документ 02 §2.1); capabilities мобильного окна задаются с `platforms` [ВНЕШН: Tauri capabilities].
