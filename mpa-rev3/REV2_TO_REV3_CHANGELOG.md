# REV2 → REV3: изменения и таблица соответствия

**Основание:** пакет REV2 (12 файлов), ревью REV2 (7 документов, находки F-01…F-26, RK-01…RK-26), ТЗ владельца REV3 от 2026-11-21.
**Язык:** REV3 написан на русском по ТЗ REV3 (ТЗ на русском, итоговые документы — на русском). Окончательное решение о языке принятых документов остаётся за OD-1.

## 1. Изменение структуры

REV2 состоял из 12 файлов по темам. REV3 — 14 содержательных документов, README и 5 реестров. Структура задана ТЗ REV3 §11. Причины:
- Секреты, сеть, сопряжение и журнал выделены из крупных документов, чтобы исправления F-01…F-04 и уточнения A–D имели одно место описания.
- Юридический документ (13) и задачи (14) сохранены как отдельные документы: в списке ТЗ их нет, но без них нарушается трассировка F-05 и задач REV2.

## 2. Исправления находок High

| Находка | Что было в REV2 | Что в REV3 | Где |
|---|---|---|---|
| **F-01** сеть и pinning | «transport client» в WebView; `fetch`/WebSocket без pinning | WebView без сетевого доступа к Desktop; только локальные команды `remote_*`; клиент TLS 1.3 + SPKI pinning в Rust; ключи и биометрия — нативный плагин; набор pin с `next_spki`; при несовпадении — только повторное сопряжение | 02 §1–§5, §10; 04 §7; 05 §3 |
| **F-02** биометрия и `payload_hash` | подпись входила в хэш, который она подписывает; повтор отклонялся или обходил подтверждение | `intent_hash` = SHA-256(JCS(Intent v1)) без доказательства; подпись над `intent_hash` + одноразовый challenge 120 с; повтор с тем же `request_id` возвращает текущее состояние и не пропускает подтверждение | 07 §2.2, §3, §7, §8.2 |
| **F-03** `shut_down` | `failed {executed: false}` | `ShutDown`, `Store`, `Internal`, прерванные вызовы → `outcome_unknown`; ссылки на код `manager.rs` проверены; автоповтор запрещён | 07 §4, §5, §6, §9 |
| **F-04** Secrets и сроки MVP | гейт G3 требовал Secrets, которого нет до Stage 7; срок MVP занижен | Stage 7 сохранён (решение владельца); MVP после Stage 7; контракт Secrets; задача MI-02a, если Stage 7 не покрывает ключи | 09; 11 §3; 01 §7; 14 (MI-02a) |
| **F-05** права и распространение | риск упомянут для iOS | отдельный документ; B1, B2, B3 открыты; публичный выпуск всех платформ — No-Go до заключения юриста; вопросы юристу; требования магазинов | 13 |

## 3. Уточнения A–D

| Уточнение | Решение REV3 | Где |
|---|---|---|
| A. Контракт Secrets | `SecretsService::scope(owner)`, операции значений и ключей, `SecretError`, владелец жизненного цикла ключа, границы доступа, отказы, без автосоздания ключа | 09 §3–§7 |
| B. Гонка прав и `received → executing` | `grant_version`/`policy_version`; повторная проверка в той же транзакции, что переход в `executing` (точка линеаризации); отзыв закрывает сессии | 06 §6; 07 §4.1; 05 §5 |
| C. Приоритет локального управления | Module Manager не меняется; допуск удалённых вызовов (1 одновременно, пауза 250 мс, очередь 4, таймаут 30 с, `busy`); худший случай — ожидание одной удалённой операции | 08 §6 |
| D. Единый механизм неопределённого исхода | одно состояние `outcome_unknown(reason)` для всех источников; сверка при старте до открытия listener; одна политика UI | 07 §4, §6, §9 |

## 5. Что не изменилось

- Роль мобильного приложения: Connected Mode + Standalone Mode.
- VPN для доступа из интернета; relay отложен.
- Без автоматической синхронизации в MVP.
- Remote Access внутри процесса Desktop (не отдельный процесс).
- ADR-001…016, `docs/DECISIONS.md`, `docs/ROADMAP.md`, порядок Desktop-этапов — **не изменены**. Предлагаемое дополнение решения 28 (шаг 0) — только в ADR-018, PENDING OWNER APPROVAL.
