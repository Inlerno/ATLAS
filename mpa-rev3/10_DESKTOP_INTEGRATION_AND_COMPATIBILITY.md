# 10. Интеграция с Desktop и совместимость (REV3)

**Статус: PROPOSED.** Заменяет REV2 `PLATFORM_COMPATIBILITY_AUDIT.md`: матрица компонентов в §5, проверка совместимости в §1–§4. Существующие ADR, `docs/DECISIONS.md` и `docs/ROADMAP.md` не меняются.

## 2. Конфликты CF-1…CF-6

| CF | Исходная проблема | Разрешение в REV3 | Изменённые документы | Влияние на Desktop | Статус | Остаётся |
|---|---|---|---|---|---|---|
| CF-1 | ADR-011: core-сервисы «не отключаются», а listener должен быть выключен по умолчанию | сервис существует всегда; listener — подтверждённая настройка; оговорка в ADR-018, ADR-011 без изменений | 03 §2, 12 (ADR-018) | нет | **PENDING OWNER APPROVAL** (направление — ТЗ REV3 §6) | принятие толкования владельцем |
| CF-2 | решение 28 и «после модулей писать некому» (`ARCHITECTURE.md:150`) против записей журнала при выходе | шаг 0 перед шагом 1; после начала остановки модулей журнал не пишется; незавершённые `executing` — сверка при старте | 03 §7, 07 §6, 12 (ADR-018) | добавить шаг 0 в `lib.rs` при реализации MPA-2 | **PENDING OWNER APPROVAL** (направление — ТЗ REV3 §6) | формальное изменение решения 28; поведение при известных пробелах выхода (TD-5, риск R-37) |
| CF-3 | решение 24 против буферов Event Gateway | буфер — доставка внешнему потребителю, как `ui_bridge`; оговорка в ADR-018 | 03 §5, 12 | нет | **PENDING OWNER APPROVAL** (направление — ТЗ REV3 §6) | принятие толкования |
| CF-4 | Remote Access как модуль требует доступа к менеджеру (запрещено решением 3) | Remote Access — core-сервис | 03 §2, 12 | нет | **PENDING OWNER APPROVAL** (направление — ТЗ REV3 §6); конфликт не возникает при выборе core-сервиса | согласовать с будущим ADR о сервисах для модулей (?-2) |
| CF-5 | новые потребители Storage; текст ADR-016 отстаёт от кода MM-5B | расширение по образцу MM-5B: типизированные операции в `storage/`, миграции с ревью владельца; формулировка — **после** обновления ADR-016 в #21 этап E | 07 §10, 10 §3 | новые операции `storage` и миграции в MPA-2 | **OPEN** до этапа E #21 | текст ADR-016 после этапа E; объём миграций (MD-06) |
| CF-6 | Remote Access нужен Secrets, который появляется на Stage 7 | Secrets остаётся на Stage 7; MVP после Stage 7; контракт — документ 09 | 09, 11 §3 | возможная задача «хранение ключа» после Stage 7 | **RESOLVED в документации** (решение владельца: ТЗ REV3 §4, §6) | входит ли хранение ключа в Stage 7 (MD-03) |

Для CF-1…CF-4 стоит PENDING, а не RESOLVED: документы между собой согласованы, но формальное изменение или толкование утверждённых решений принимает владелец при G0.

## 3. Требования MPA → Desktop

| Требование MPA | Компонент Desktop | Этап ROADMAP | Зависимость | Блокер |
|---|---|---|---|---|
| Module Manager для удалённого управления модулями | Module Manager | Stage 1 (готово; #21 этап E открыт) | #21 этап E (тест убийства процесса, документация, журнал) | Stage 1 не закрыт |
| CSP вебвью | `tauri.conf.json` | вне этапов; #13 «Следующие issue» («до сетевых функций») | задача CSP (будущая, по #13) | `csp: null` |
| Хранение токенов | Secrets | **Stage 7** | Stages 0–6 | Secrets отсутствует |
| Хранение ключа TLS, генерация, ротация | Secrets | Stage 7 или отдельная задача после Stage 7 (MI-02a) | Stage 7 | не запланировано явно → **новая задача** |
| Remote Access (listener, аутентификация, журнал, Event Gateway) | новый core-сервис | **нет в ROADMAP** → новые задачи MI-02…MI-09 после G3 | G3 | не запланировано → **новые задачи** |
| Шаг 0 выхода | `lib.rs` | вместе с Remote Access | ADR-018 | решение по CF-2 |
| Таблицы журнала, реестра, аудита | Storage | вместе с Remote Access | обновлённый ADR-016 (#21 E), ревью миграций | CF-5 |
| `RequestContext` в Policy | Policy | Stage 5 (проектирование) | OD-14 | OD-14 |
| Удалённые команды ПК | Policy + Windows tools | Stage 5 | Stage 5 | Stage 5 не начат |
| Чат с LM Studio | AI provider + чат | Stage 3 | Stage 3 | Stage 3 не начат |
| История, память | Memory | Stage 6 | Stage 6 | Stage 6 не начат |
| Поля происхождения записей (UUID, `origin_instance_id`, `version`) | схемы Stage 6 | Stage 6 (проектирование) | MD-04 | — |
| Telegram principal | Telegram | Stage 7 | OD-14 (T1/T2/T3) | OD-14 |
| Сигнал локальной активности (вариант) | `commands/` | вместе с Remote Access | MD-05 | решение при MPA-2 |
| Экспорт диагностики без секретов | Diagnostics | Stage 8 | контракт 09 §6 | — |

Новые возможности Desktop, которых нет в ROADMAP, — Remote Access и, возможно, хранение ключа в Secrets. Они оформлены как явные будущие задачи **после** Stage 7 (документ 14) и порядок утверждённых этапов не меняют.

## 4. Порядок MM-5A → MM-6 → MM-7 → SQLite → MM-5B и этап E ADR-016

|---|---|---|

| SQLite foundation (ADR-016) | слита | основа для журнала |
| MM-5B (#21) | этапы A–D слиты (PR #36–#39), этап E открыт | MPA зависит от завершения: обновлённого текста ADR-016 (сейчас `DECISIONS.md` перечисляет только `new/open/close/close_within`, а код уже имеет `read_module_config`, `write_module_configs`, `replace_module_config_if`, `storage/mod.rs:299–324`) и теста убийства процесса — образца для тестов сверки журнала |
| Порядок | не меняется | MPA добавляет работу только после G3 |
